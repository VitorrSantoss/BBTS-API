## 🎯 Sobre o Projeto

O **BBTS API** é um sistema backend robusto para gerenciamento completo de informações curriculares. A aplicação permite que usuários cadastrem e organizem seus dados profissionais de forma eficiente, incluindo:

- **Dados Pessoais**: informações básicas do usuário
- **Experiências Profissionais**: histórico completo de empregos
- **Certificações**: cursos e certificados obtidos
- **Idiomas**: registro de idiomas com níveis de proficiência
- **Tecnologias**: habilidades técnicas com níveis de domínio

O projeto foi desenvolvido seguindo os padrões REST e boas práticas do Spring Framework, com arquitetura em camadas (Controller, Service, Repository) e uso de DTOs para proteção de dados sensíveis.

## ✨ Funcionalidades

- ✅ Cadastro completo de usuários com validação de dados
- ✅ Gerenciamento de experiências profissionais (emprego atual/anterior)
- ✅ Registro de certificações com suporte a arquivos
- ✅ Cadastro de idiomas com níveis de proficiência (INICIANTE até NATIVO)
- ✅ Registro de tecnologias com níveis de habilidade (JUNIOR, PLENO, SENIOR)
- ✅ Upload de foto de perfil e certificados
- ✅ Cadastro completo em uma única requisição (multipart/form-data)
- ✅ Validação de dados com Bean Validation
- ✅ Proteção de dados sensíveis através de DTOs
- ✅ Documentação interativa com Swagger/OpenAPI
- ✅ Configuração de CORS para integração com frontend

## 🏗️ Arquitetura

O projeto segue uma arquitetura em camadas bem definida:

```
┌─────────────────────────────────────┐
│         Controller Layer            │  ← Requisições HTTP
├─────────────────────────────────────┤
│          Service Layer              │  ← Lógica de negócio
├─────────────────────────────────────┤
│        Repository Layer             │  ← Acesso a dados
├─────────────────────────────────────┤
│         Database (MySQL)            │  ← Persistência
└─────────────────────────────────────┘
```

### Camadas:

- **Controller**: Recebe requisições HTTP, valida entrada e retorna respostas
- **Service**: Contém a lógica de negócio da aplicação
- **Repository**: Interface com o banco de dados usando Spring Data JPA
- **Model**: Entidades JPA que representam as tabelas do banco
- **DTO**: Objetos de transferência de dados para proteção de informações sensíveis

## 🔧 Instalação

### 1. Clone o repositório

```bash
git clone https://github.com/seu-usuario/bbts-api.git
cd bbts-api
```

### 2. Crie o banco de dados

Conecte-se ao MySQL e execute:

```sql
CREATE DATABASE bbts_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 3. Configure as credenciais

Edite o arquivo `src/main/resources/application.properties`:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/bbts_db
spring.datasource.username=seu_usuario
spring.datasource.password=sua_senha
```

## ⚙️ Configuração

### application.properties

Configurações disponíveis:

```properties
# Nome da aplicação
spring.application.name=bbts-api

# Configuração do banco de dados
spring.jpa.hibernate.ddl-auto=update
spring.datasource.url=jdbc:mysql://localhost:3306/seu_banco
spring.datasource.username=seu_usuario
spring.datasource.password=sua_senha
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

# Mostrar SQL no console (opcional - descomente para debug)
#spring.jpa.show-sql=true
#spring.jpa.properties.hibernate.format_sql=true
```

### CORS

A API está configurada para aceitar requisições de:
- `http://localhost:5500`
- `http://127.0.0.1:5500`
- `http://localhost:3000`

Para adicionar novas origens, edite `CorsConfig.java`:

```java
.allowedOrigins(
    "http://localhost:5500",
    "http://127.0.0.1:5500",
    "http://localhost:3000",
    "https://seu-frontend.com"  // Adicione aqui
)
```

### Login

| Método | Endpoint | Descrição |
|--------|----------|-----------|
| POST | `/auth/login` | `{ email, senha, perfil: COLABORADOR \| GESTOR }`. Senhas ficam com BCrypt; senha antiga em texto puro é aceita uma vez e convertida. Quem não tem senha define a senha no primeiro acesso. |

### Perfil do colaborador

| Método | Endpoint | Descrição |
|--------|----------|-----------|
| GET | `/usuarios/{id}/completo` | Dados, equipe com mínimos, competências, lacunas, jornada, idiomas, tecnologias, experiências, certificados e formação |
| PUT | `/usuarios/{id}/competencias` | `{ sigla, nivel }`: cria ou atualiza o nível numa competência do catálogo |
| DELETE | `/usuarios/{id}/competencias/{sigla}` | Remove a competência do usuário |
| GET / PUT | `/usuarios/{id}/foto` | Foto de perfil (PUT multipart, campo `foto`, até 5 MB) |

Lacunas e jornada não são gravadas: lacuna é cada competência mínima da equipe que o colaborador não atinge (ausente conta como nível 0), e a jornada lista os cursos dessas competências.

### Equipes, competências e feedback

| Método | Endpoint | Descrição |
|--------|----------|-----------|
| GET | `/equipes?gestorId=` | Equipes (do gestor, se informado) com membros, níveis e mínimos |
| GET | `/equipes/{id}` | Uma equipe |
| POST | `/equipes` | `{ nome, foco, descricao?, gestorId, emails? }` |
| POST | `/equipes/{id}/membros` | `{ emails }`: adiciona colaboradores cadastrados; devolve `adicionados` e `naoEncontrados` |
| DELETE | `/equipes/{id}/membros/{usuarioId}` | Tira o colaborador da equipe |
| GET / POST | `/competencias` | Catálogo SFIA (sigla, nome, categoria, nível máximo) |
| GET | `/feedbacks?destinatarioId=` ou `?autorId=` | Feedbacks recebidos ou enviados |
| POST | `/feedbacks` | `{ autorId, destinatarioEmail, tipo: POSITIVO \| DESENVOLVIMENTO, mensagem }` |
| CRUD | `/formacoes` | Formação acadêmica (corpo com `usuario: { id }`) |
| GET | `/certificacoes/{id}/arquivo` | Arquivo do certificado |

Erros saem como `{ "status": 400, "message": "..." }`.

### Carga inicial

`config/CargaInicial.java` roda na subida e é idempotente: cadastra o catálogo SFIA e os cursos quando o catálogo está vazio e, uma única vez (quando não há equipes), cria as equipes de exemplo, define os gestores e preenche níveis, idiomas, tecnologias, experiências, formação e feedbacks dos usuários de exemplo, reaproveitando quem já existe pelo e-mail. Desligue com `CARGA_INICIAL=false`.
